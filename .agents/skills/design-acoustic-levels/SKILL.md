# 声学关卡设计

在回声工坊仓库根目录执行下列命令。若把本技能安装到其他工作区，先取得完整的 silent-chamber-workshop 工具仓库，命令和源码路径均以工具仓库为基准。先读 `src/ugc/model.js` 的草稿格式与 `src/ugc/catalog.js` 的素材规则。玩家在黑暗里通过声波认识环境，每个危险都应有可察觉的先兆，每个关键岔路都应给出值得选择的代价。

## 先试地图，再放机关

运行 `npm run review:mazes`，用浏览器打开 `output/trials/maze-algorithm-trials.html`。比较 DFS、Prim 风格和 Growing Tree 的 96 张原始底图。观察岔点、盲支深度、转角与回路；筛掉可以沿外围直达、必经路线绕开了大部分探索的布局。保留候选算法、种子及取舍理由。

用 `node scripts/generate-draft.js 314 growing-tree draft.json` 生成可导入草稿。两个临时端点取自迷宫图直径，定稿时根据设计意图调整。若重新选择种子，换一个输出文件名。网页里的“新建 → 生成迷宫”也能快速得到可编辑地图，使用另一套自动取种子的布局算法。

## 写下玩家的选择

填写 [关卡设计单](references/level-contract.md)。写清中央问题、至少两种有不同代价的应对方式、第一次能听见线索的位置，以及判断失误之后可恢复的路径。把主线分为发现、承诺行动、后果、恢复四步。列出起点、出口、触发条件、岔路和等待位置。用 `src/world.js`、`src/hazards.js`、`src/devices.js` 核对机关与敌人行为，用 `src/propagation.js` 核对声波能否抵达。深坑吞声，墙和柱子的反射要靠近玩家可走的位置。新增设计不放弓箭发射器，旧的自定义草稿可以导入。

## 制作可试玩草稿

在网页选择“导入”，粘贴生成的 JSON。移动起点与出口，增加代表关键取舍的声锁、敌人、地形或机关。有连线的素材需依次点两个端点。也可在脚本中用 `createEditorState` 和 `applyEditorAction` 制作同样的修改。每类关键元素分别说明负责提示、施压、开启、替代路线或恢复中的哪一项。保存最终 JSON，通关所需的地形和对象均应来自该文件。

在右侧“关卡检查”修复错误，再按 P 试玩。移动用方向键或 WASD，Shift 轻走，站定后按住空格蓄力再松开，E 朝指针投石。出生自动声波半径为 2.5 格，主动声波为 4–17 格，蓄满需要 1.5 秒。在危险时间窗内计算这段蓄力时间。可通过“导出 → 游戏关卡码”传给其他玩家。

## 验证并交付

用 `importDraft` 加载草稿、`createPreviewWorld` 创建模拟、`routeFor` 检查路线。完成一条符合真实输入的成功路径，记录 `world.complete` 和 `world.failed`。再演示一种失误或代价较高的选择，记录声波到达、敌人反应、通行或耗时的差异。分别移除关键元素，确认路线、风险或决策的变化。静态连通性不能代替实际试玩。将尚未进行的真人盲测明确标为待测。

交付最终草稿、种子和算法、设计单，并依据 [HTML 评审要求](references/html-review.md) 从草稿生成可离线打开的地图说明，包含底图/成图、推荐/备选路线及声学判断依据。运行 `npm test` 与 `npm run build`，在浏览器从导入、试玩到导出走完一遍。
